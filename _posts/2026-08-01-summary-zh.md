## [无状态 MCP 2.0 重燃兴趣，催生 mcp-explorer 与 datasette-mcp](https://simonwillison.net/2026/Jul/31/stateless-mcp/#atom-everything) ⭐️ 8.0/10

MCP 2.0 作为无状态协议发布，工具可通过单次 HTTP 请求调用，取代了之前的两步会话初始化，极大简化了客户端和服务器的实现。这启发 Simon Willison 开发了 mcp-explorer 和 datasette-mcp，展示了更便捷的集成方式。 转向无状态 MCP 降低了协议的复杂性，使可扩展的服务器和客户端实现变得极为容易。这很重要，因为它解决了让智能体‘Skills’盖过 MCP 的关键弱点，有望将 MCP 重新确立为一种更安全、更可审计的 LLM 智能体工具访问方式。 新的无状态 MCP 使用 MCP-Protocol-Version 和 MCP-Method 等头部在单次 HTTP 请求中传递会话和方法信息，客户端信息移至 JSON 主体的 _meta 参数。一个关键限制是服务器不能跨调用依赖会话状态，因此多步骤工作流可能需要 Tasks 等扩展，但这种设计消除了会话关联需求，大大简化了扩展。

rss · Simon Willison · 7月31日 23:13

**影响**: 短期内，开发者可以用更少的代码构建 MCP 服务器和客户端，加快原型开发并推动更广泛的采用。长期来看，无状态 MCP 的可扩展性可能使其成为云端智能体工具集成的标准，像 mcp-explorer 这样的工具降低了调试和探索 MCP 服务的门槛，有望加速生态系统增长。AI 应用开发者、API 构建者以及在生产环境中部署 LLM 智能体的公司将因运维开销降低和安全审计能力提升而受益。

**背景**: MCP（模型上下文协议）是 Anthropic 推出的开放标准，定义了 LLM 智能体如何发现并使用外部工具。原有协议是有状态的，需要先建立会话才能调用工具，增加了复杂性并限制了可扩展性。这导致一些开发者更青睐“Skills”这类直接给予智能体终端和互联网访问的替代方案，尽管这些方案风险更高。新的无状态版本类似于 HTTP，每个请求都是自包含的。
