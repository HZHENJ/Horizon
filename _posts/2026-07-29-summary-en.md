## [Open-Source Engine Runs Gemma 4 26B on M-Series Macs with Only 2 GB RAM](https://github.com/drumih/turbo-fieldfare) ⭐️ 8.0/10

A new Swift/Metal inference engine called TurboFieldfare streams routed experts from SSD to run the 4-bit quantized Gemma 4 26B model on any M-series Mac using only about 2 GB of RAM, achieving 5–6 tok/s on an M2 MacBook Air and 31–35 tok/s on an M5 MacBook Pro. This approach challenges the assumption that entire large language models must reside in RAM, making advanced on-device AI feasible on resource-constrained hardware and opening up possibilities for edge computing with limited memory. The engine achieves low RAM usage by caching shared model parts and KV cache in memory while streaming only the required expert weights from SSD, using parallel pread to overlap I/O with GPU compute. However, it currently only supports 4-bit quantized models and relies on fast SSDs, with notable performance variation across Mac models.

hackernews · gitpusher42 · Jul 29, 15:05 · [Discussion](https://news.ycombinator.com/item?id=49098510)

**Impact**: In the short term, users with entry-level Macs can run a 26B parameter model without upgrading hardware, lowering the barrier for personal AI experimentation. In the longer term, this technique could inspire similar memory-efficient inference engines for other devices, potentially enabling powerful AI assistants on smartphones and IoT devices without requiring large RAM.

**Background**: Mixture of Experts (MoE) models like Gemma 4 26B contain multiple 'expert' sub-networks, but only a subset is activated per token, reducing compute. The model uses 26B total parameters with only 4B active per token. SSD offloading is a technique where model weights are stored on disk and fetched as needed, but typically incurs high latency; this engine mitigates that by caching and parallel reads.

## [AI Worms Can Self-Propagate via Copilot for Word Using Hidden Instructions](https://enklypesalt.com/posts/context-collapse-part3-ai-worming-through-word/) ⭐️ 8.0/10

Security researcher Håkon Måløy discovered that malicious instructions hidden in a Word document can hijack Microsoft Copilot for Word, causing it to modify documents and spread the attack to other files, functioning as a self-replicating AI worm. This highlights a fundamental vulnerability in AI-integrated applications: large language models cannot reliably distinguish between trusted instructions and untrusted data, making prompt injection attacks a persistent and pervasive threat. The attack works by embedding malicious prompts in a document's content, including hidden text like white-on-white text, which Copilot interprets as commands. As of now, there is no known robust mitigation, as the underlying issue of separating instructions from data remains unsolved.

hackernews · Canopy9560 · Jul 29, 11:44 · [Discussion](https://news.ycombinator.com/item?id=49096188)

**Impact**: In the short term, users with Copilot for Word are at risk of document tampering and potential data exfiltration if they open malicious files. Over time, this could undermine trust in AI productivity tools, force software vendors to implement stricter isolation between data and instructions, and potentially slow the adoption of AI assistants in sensitive environments.

**Background**: Microsoft Copilot for Word is an AI assistant that helps users draft and edit documents. Prompt injection is a security vulnerability where an attacker embeds malicious instructions into data that an AI model processes, tricking it into performing unintended actions. An AI worm is a type of malware that autonomously spreads by leveraging AI capabilities.
