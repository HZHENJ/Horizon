## [Stateless MCP 2.0 Revives Interest, Leads to mcp-explorer and datasette-mcp](https://simonwillison.net/2026/Jul/31/stateless-mcp/#atom-everything) ⭐️ 8.0/10

MCP 2.0 was released as a stateless protocol, where tools can be called with a single HTTP request instead of the previous two-step session initialization, greatly simplifying client and server implementation. This inspired Simon Willison to build mcp-explorer and datasette-mcp, demonstrating the easier integration. The shift to stateless MCP reduces the protocol's complexity, making it vastly easier to implement scalable servers and clients. This matters because it addresses a key weakness that allowed agent 'Skills' to eclipse MCP, potentially re-establishing MCP as a safer, more auditable way to give LLM agents access to tools. The new stateless MCP uses headers like MCP-Protocol-Version and MCP-Method to convey session and method info in a single HTTP request, with client info moved to a _meta parameter in the JSON body. A key limitation is that servers cannot rely on session state across calls, so multi-step workflows may require extensions like Tasks, but this design eliminates the need for session affinity, greatly simplifying scaling.

rss · Simon Willison · Jul 31, 23:13

**Impact**: Short-term, developers can build MCP servers and clients with significantly less code, enabling faster prototyping and broader adoption. Long-term, the scalability of stateless MCP could make it the standard for cloud-based agent tool integrations, and tools like mcp-explorer lower the barrier for debugging and exploring MCP services, accelerating ecosystem growth. AI application developers, API builders, and companies deploying LLM agents in production will benefit from reduced operational overhead and improved security auditability.

**Background**: MCP (Model Context Protocol) is an open standard from Anthropic that defines how LLM agents can discover and use external tools. The original protocol was stateful, requiring a session to be established before tool calls, adding complexity and limiting scalability. This led some developers to prefer alternatives like 'Skills' that give agents direct terminal and internet access, though those approaches are riskier. The new stateless version is akin to HTTP, where each request is self-contained.
