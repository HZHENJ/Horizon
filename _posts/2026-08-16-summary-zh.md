## [Cloudflare 切换域名服务器后静默注入分析脚本](https://news.ycombinator.com/item?id=49322107) ⭐️ 8.0/10

有 Hacker News 用户反映，在将域名服务器切换到 Cloudflare 以便用子域提供 R2 存储桶服务后，Cloudflare 自动向其原本无 JavaScript 的纯 HTML 网站注入了 Web Analytics 分析脚本 beacon。用户必须进入 Analytics 仪表板、添加站点后再关闭代码片段，才能将其移除。 这暴露了一个隐私和信任问题：Cloudflare 在其代理背后静默修改客户网页，把本应主动选择的功能变成了默认开启、需要手动退出。Cloudflare 服务约 21% 的网站，这类默认行为影响范围很广，也引发对用户同意、透明度和供应商控制力的担忧。 被注入的脚本来自 static.cloudflareinsights.com/beacon.min.js，并带有包含 token 的 data-cf-beacon 属性。有评论指出，使用 script-src 'self' https://only-scripts-allowed-from-here.com 这类内容安全策略 meta 标签可以阻止该脚本；并且只有当 Cloudflare 代理 HTTPS 流量时才会注入，仅使用 Cloudflare DNS 则不会。

hackernews · stagas · 8月16日 17:49

**影响**: 短期内，通过 Cloudflare 代理流量的网站所有者可能在不知情的情况下向访客加载第三方分析脚本；他们需要检查 HTML、关闭该功能，或使用内容安全策略来阻止外部脚本。长期来看，这可能加速用户迁往 Bunny.net 等替代 DNS/代理服务商，加大对 Cloudflare 隐私声明的审查力度，并促使 Cloudflare 将分析功能改为严格的选择加入。

**背景**: Cloudflare 是一家大型互联网基础设施公司，充当访客与网站托管服务之间的反向代理，提供 CDN、安全和 DNS 等服务。R2 是 Cloudflare 的对象存储产品，免出口流量费。当域名的流量通过 Cloudflare 代理、而不仅仅是使用 Cloudflare DNS 时，Cloudflare 就可以修改响应内容，分析脚本正是这样被插入的。
